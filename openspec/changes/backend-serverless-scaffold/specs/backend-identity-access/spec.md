## Purpose

管理帳號註冊、角色（老師/學生/管理者）、老師輕量身分驗證審核與 Admin 強化驗證，是其他所有後端能力運作的權限基礎。

## ADDED Requirements

### Requirement: 學生註冊欄位規則
系統 SHALL 將手機號碼設為學生註冊的必填欄位，缺少手機號碼的註冊請求 SHALL 被拒絕；Email 為選填欄位。

#### Scenario: 缺少手機號碼的註冊請求被拒絕
- **WHEN** 註冊請求未包含手機號碼
- **THEN** 系統回應驗證錯誤並拒絕建立帳號

### Requirement: 老師輕量身分驗證審核流程
系統 SHALL 要求老師提交真實姓名、身分證字號（加密儲存，不對學生顯示）、身分證正反面照片（存於私有物件儲存，僅管理者可讀取）、撥款銀行帳戶；撥款帳戶戶名 SHALL 與註冊時填寫的真實姓名進行字串比對，不一致 SHALL 拒絕送出。送出後進入「待審核」狀態；管理者審核通過後轉為「已認證」，退回時標記「已退回」並記錄理由。老師帳號在轉為「已認證」之前，SHALL 被拒絕任何建立或發佈課程的請求。

#### Scenario: 戶名與真實姓名不一致擋下送出
- **WHEN** 老師提交的撥款帳戶戶名與註冊時填寫的真實姓名不相同
- **THEN** 系統拒絕該次送出並回傳戶名不一致的錯誤訊息

#### Scenario: 未通過驗證前建立課程被拒絕
- **WHEN** 驗證狀態為「待審核」或「已退回」的老師呼叫課程建立 API
- **THEN** 系統回應 403 並拒絕建立

### Requirement: 角色與 Row-level 授權
系統 SHALL 限制老師只能存取或操作自己 `teacher_id` 名下的課程、訂單與工單資料；學生只能存取自己 `student_id` 名下的訂單與工單資料。任何跨越他人資料範圍的請求 SHALL 被拒絕。

#### Scenario: 老師嘗試存取他人課程的訂單被拒絕
- **WHEN** 老師 A 呼叫 API 嘗試讀取老師 B 名下課程的訂單清單
- **THEN** 系統回應 403 並拒絕回傳資料

### Requirement: Admin 強化驗證
系統 SHALL 要求管理者帳號完成多因素驗證（MFA）才能取得有效登入 session；MVP 階段管理者角色 SHALL 僅支援單一權限層級，不提供分級角色。

#### Scenario: 未完成 MFA 無法取得有效 session
- **WHEN** 管理者僅完成帳號密碼登入，尚未完成 MFA 驗證步驟
- **THEN** 系統不核發可用於呼叫其他 API 的有效 session/token
